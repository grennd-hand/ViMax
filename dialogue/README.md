# ViMax 群聊剧本模式

母本坐席内容确定对话目标、必要说明和原始业务信息，原账号无需沿用。重新设置参与者、角色卡、语言和总条数，生成后按原九列导出 Excel / JSON。

本模式移入用户原有 `ai-script-dialogue-generator` 的导入、人物记忆、校验功能；生成器改为 ViMax `Screenwriter` 的故事规划和剧本写作。界面直接集成到 ViMax 原工作台，保留群聊流程、剧本记录和语言模型设置，原工作台已中文化。独立数据库在 `.vimax/dialogue/`，原应用及其数据库不参与新模式运行。

## 本地运行

在 ViMax 根目录安装 Python 3.12 及依赖：

```powershell
uv venv .venv --python 3.12
uv pip install --python .venv/Scripts/python.exe -r dialogue/backend/requirements.txt
npm ci --prefix web
npm run build --prefix web
```

设置 `MODEL_API_BASE_URL`、`MODEL_API_KEY` 环境变量，或在启动时指定接口地址与 Windows DPAPI 密钥文件：

```powershell
./scripts/start-dialogue.ps1 -BaseUrl https://your-provider.example/v1 -KeyFile C:/private/model-key.dpapi
# 另开一个终端
npm start --prefix web
```

访问 `http://127.0.0.1:4173`，在原工作台选择“群聊剧本”。群聊后端默认端口9014；可通过 `VIMAX_DIALOGUE_URL` 调整 Web 代理目标。只有一套 Web 界面；后台接口由原 Web 服务代理。访问 `/dialogue-api/health` 可检查服务是否已配置模型。

## 生成与校验

ViMax 先依据坐席母本和确认目标生成事件线，再生成结构化群聊草稿；条数、回复编号、身份与母本原值经过校验，随后通过各角色独立会话广播并保存。整段复核检查目标实际完成、人物选择和重复内容，根据问题修订后重新复核。失败保留草稿及已接受消息，可继续或重试，不显示为成功。

新模式保留角色知识库、独立人物记忆和公开原话索引。新参与者无需全部发言；验收以已确认内容目标为准。模型运行和导出均在本地，不操作外部业务网站或聊天平台。

规划复用 ViMax 小说模块的 Event 因果链结构。新剧本使用第3版交流规划：人物卡先转为个人需要、注意点、接话与忽略条件及表达习惯；话题提供触发与停止条件，不分配消息区间，也不要求全部演完。旧剧本保留原规划格式，可以继续读取与恢复。

写作仍按每段最多30条续写，读取此前完整公开对话和按角色归属的个人动机。普通陈述、玩笑不要求有人回应，不按人头补发言；关系从陌生群友开始，随实际公开互动变化。跨全文近似表述作为检查候选传给续写与整段复核，不能单凭相同链接或代码判重复，也不自动判定自然度通过。规划、分段写作和复核沿用现有调用流程，不增加逐角色模型调用。

只有群聊写作界面，图片、视频、分镜及独立小说操作入口已移除。生成文件在当前剧本的“检查与导出”区域下载。程序验证条数、原值及因果顺序；自然度需要人工完整阅读，程序通过不代表读感已经达标。

模型设置可保存推理强度低、中、高或模型默认。角色设置页可选择 GPT-6 Sol，并为本次剧本单独设置推理强度，留空则沿用模型设置。规划、写作和修订保留实际请求的模型与强度记录；接口不支持明确指定的强度时显示失败，不自动降低。

新建任务使用第4版消息格式，可输出文本、图片或图片加文本。母本需要群内截图时，剧本保留带 `SCREENSHOT_` 图片码的素材占位消息，导出保留九列；素材需要后续补齐，这不代表已获得真实截图或已执行外部操作。旧任务继续按原有格式读取及续写。

第4版每份完整初稿和完整修订稿在数据目录的 `versions/<任务编号>/R000-<哈希>/` 分别归档，包含原始运行记录、Markdown、Excel及文件哈希，运行记录的 `candidate_versions` 保存索引。相同台词不重复归档，原捕获状态不随最终检查覆盖；生成检查和人工审阅仍分别记录。
