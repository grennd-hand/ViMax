# 中文工作台与母本群聊验证

## 群聊安排感优化（第二版，2026-10-14）

新运行使用五段各30条的续写方式，每段读取之前已生成的公开台词、每个人自己的近期发言、收到的回应、明确选择以及当下处境。已写片段持久化，暂停或失败后从片段末尾继续，避免重写前文。150条通常由一次规划、五次续写和一次完整复核构成；比第一版整篇一次写作增加四次正常写作调用。

规划保留小说Event的因果结构，并增加业务、日常、关系话题及各自私有处境。移除固定第8/12条转场、主角与陪练设定、最后10%才完成任务以及必须坐席最后总结。开场仍先寒暄再了解用途，但阶段由实际台词决定；原值和业务因果顺序仍严格检查。目标可以较早完成，后续继续有具体内容的日常交流。

新版内部台词携带回复编号、间隔秒与交流阶段，导出仍为原九列；普通接话使用回复编号0。程序拒绝整篇几乎每条都引用回复、全部相同的间隔以及开场顺序倒退。间隔属于模拟播放安排，不代表真实平台消息时间。整段复核新增陪练式接话、重复证明自主性、无新背景重问已解决问题等检查，统计证据随结果保存。

仍使用ViMax Screenwriter逐段续写，人物状态按所属角色隔离并在下一段参与创作；不是每个角色逐条独立调用模型。界面说明改为“人物会话记忆”，显示已写条数。旧运行继续兼容四项台词格式和第一版开场规则。

后台38项测试、Web15项测试、TypeScript、编译、构建和diff检查通过，包含分段全局编号、阶段与排程一致、跨段公开/私有记录、检查点恢复以及调用记录保留。

同一母本、八种人格和GPT-6 Sol high生成150条，五段续写后经过自动复核修订，再根据人工通读反馈进行一次模型修订，没有手工改写模型台词。最终结构检查与复核通过，目标达成，Excel九列150条与JSON及运行消息逐条一致。样例中第66条首次完成申请，结尾由客户1接普通生活话题。引用回复由上一版149条降到1条，模拟间隔由统一1秒变为4至305秒；这些是编排差异，不能单独证明真实感。人工通读认为陪练与自述动机明显减少，日常话题仍有篇幅感；此次属于人工反馈辅助的模型修订验收，不是全自动自然度稳定通过。

本次最终样例和验证结果见本地忽略目录 `outputs/自然群聊优化-150条-20261014/`。下文记录第一版与更早版本的历史验收，不能作为本次自然度结论。

## 人格库与寒暄开场（第一版，2026-10-14）

ViMax写作上下文现已接入人格介入值，零值不传角色卡，非零值要求选择、接话对象和表达随卡片变化。仍由一个Screenwriter写整段，再广播到角色会话记忆；这次没有改成逐角色独立采样。

后台28项测试、Web15项测试、TypeScript检查及生产构建通过，包含开场与排程一致、旧运行兼容、人格介入值及提前公布原值的回归检查。

## 精简与小说逻辑复用

浏览器验证仅保留三个入口：群聊剧本、新建剧本、模型设置。新建进入空白母本导入页，旧150条剧本可重新打开，Excel与JSON导出入口保留。切换模型设置时不卸载当前剧本页面，配置保存仅发送语言模型部分。删除97个不再使用的前端依赖及旧影视组件；生产JS由408.63kB降至约207.27kB，CSS由62.60kB降至27.97kB。

群聊规划直接继承上游 `interfaces/event.py` 的 Event 模型，补充消息区间、起因、结果和跨事件连续性约束；复用上游容错JSON解析器。接入现有一次规划调用，不额外调用整套小说转视频流程。早期一次模型规划输出16个事件，连续覆盖1至150条，结构校验通过；当时尚未重跑成稿，后续完成记录见下文。
