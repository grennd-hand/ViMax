# 中文工作台与母本群聊验证

## 实现范围

ViMax 原 Web 工作台已精简为母本群聊流程、剧本记录和语言模型设置，移除影视聊天、图片、视频、分镜、小说操作界面及其前端模块。群聊模式通过可选提示词使用 ViMax 的规划与写作方法。母本原账号保留在导入记录中，不强制沿用，不要求每个参与者都发言；坐席内容目的、原值和必要因果顺序是约束。

原应用及其数据库未修改。本模式数据保存在 `.vimax/dialogue/`，生成文件进入 ViMax 项目的 `.working_dir/`。真实母本和运行记录均未纳入版本控制。

## 本地检查

- 后台：20项针对回复关系、原值、自由人物、独立记忆、制作口吻、退出连续性、编剧默认兼容性、小说事件结构和推理参数的测试通过。
- Web：删除旧影视模块及其专属测试后，15项现有测试通过，含上传二进制内容、进度流代理和推理配置保存回归。
- Web生产构建及 TypeScript 类型检查通过。
- Python编译及 `git diff --check` 通过。

## 真实母本

通过工作台的同源接口导入106条消息、43条坐席消息的母本，确认原坐席目的，设置150条群聊。角色重新选择，原母本账号无需出场。未访问母本中的业务链接，也未向聊天平台发送生成内容。

第一轮和第三轮达到条数及坐席目的，但因连续重复和汇报口吻未通过完整复核，保留失败记录。第二轮程序检查通过，人工发现退出后继续说话及制作口吻，随后新增相应检查。第四轮改为一位主要参与者完整执行流程，其他人按各自兴趣参与，使用 GPT-5.6 Terra 生成，并在原运行中继续修订，最终自动复核通过：150条、目标达成、问题列表为空。

通读150条后人工校对4处：纠正没有依据的每日任务保证、提前引用尚未说明的原话，以及两处重复表达。该样例属于自动生成和修订后人工校对的验收，不能作为全自动自然度稳定通过的证明；人物表达仍有偏说明式和确认式的段落。

校对后重新核验母本原值、回复关系和结构，并从统一工作台接口导出。Excel为原九列、150条数据，消息编号连续，内容逐条与JSON一致。导出文件及人工修改前后记录保存在本地忽略目录，未上传GitHub。

本记录只说明本次检查，单次样例不代表所有母本都能稳定生成自然对话。未部署服务器。

## 精简与小说逻辑复用

浏览器验证仅保留三个入口：群聊剧本、新建剧本、模型设置。新建进入空白母本导入页，旧150条剧本可重新打开，Excel与JSON导出入口保留。切换模型设置时不卸载当前剧本页面，配置保存仅发送语言模型部分。删除97个不再使用的前端依赖及旧影视组件；生产JS由408.63kB降至约207.27kB，CSS由62.60kB降至27.97kB。

群聊规划直接继承上游 `interfaces/event.py` 的 Event 模型，补充消息区间、起因、结果和跨事件连续性约束；复用上游容错JSON解析器。接入现有一次规划调用，不额外调用整套小说转视频流程。早期一次模型规划输出16个事件，连续覆盖1至150条，结构校验通过；当时尚未重跑成稿，后续完成记录见下文。

## 用户提供母本与 GPT-6 Sol 高强度试跑

用户提供的新母本导入106条消息、43条坐席内容。按用户要求切换到 `gpt-6-sol`、`reasoning_effort=high`，实测接口返回200并报告相同模型名。工作台模型设置及每次剧本配置都支持推理强度；明确指定的强度若被接口拒绝则报错，不静默移除。运行的规划、写作和结构修订记录均显示 `gpt-6-sol / high`。

新事件规划生成14个事件，覆盖150条。规划、完整写作及一次结构修订完成后，整段复核通过：150条、目标达成、问题列表为空。人工通读全部台词，未改动模型成稿；主要操作顺序与原值完整，局部仍有重复确认。这个结果证明本次内容目标和结构通过，不表示自然度已稳定达标。

同源接口导出的Excel为原九列表头、150条数据，首尾坐席、编号连续、回复引用合法，内容逐条与JSON一致。本次母本、成稿与运行证据保存在本地忽略目录，未纳入PR。生成目标仅为剧本中的材料提交，未要求或操作真实付款、经理回复、业务链接与聊天平台。
