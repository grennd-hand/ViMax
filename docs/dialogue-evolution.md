# 群聊版本归档与审阅

本轮脚本位于 `.vimax/deploy/`，完整产物位于本地 `outputs/自然群聊-20261015/`。母本、原文和私有模型配置不提交到 GitHub。

每个编号保存150条完整稿。局部修订通过 ViMax Screenwriter 返回指定范围的新台词，与父稿的未变消息合成完整稿；先归档，再检查合同、广播与语义。实际父稿、源码、模型强度和原始响应分别记录。只改间隔、空响应或与父稿相同的正文不能充作新内容。

主审报告记录实际阅读方法；中间稿可以使用已读父稿逐条比对全部150对象、读全部变化与上下文的全量覆盖，独立审阅者仍从头读取全部150条。最终推荐稿重新从头阅读全文。程序模型复核是否执行单独记录，人工候选不等于模型通过。

`prepare-evolution.py` 将父稿精确文件SHA及两份报告绑定到输入。`evolve-natural-patch.py` 支持最多40条修改，`--preserve-delay` 确定性沿用父稿间隔，同时保留模型原始值。`--revision-label R001` 新建修订目录；同编号父稿必须是较早修订，目录身份、真实父SHA与报告必须一致，旧目录不可覆盖。V40必须执行真实完整模型复核。

模型意见与人工判断冲突时，保留双方原始记录，核对具体原句。需要修正则新建修订稿，不回写已登记原文或旧报告。`evolution-corrections.json` 通过原文件精确SHA附加显示说明及同编号代表，不篡改原状态或原人工结论。

`register-evolution.py` 冻结双人报告、快照校验和与索引；`finalize-evolution.py` 核查V01–V40正式代表正文去重，且推荐稿真正完成模型全文复核，再生成选择说明和导出包。生成代码标签对应产品提交；忽略目录中的实际生成helper另由源码副本与哈希追踪。

工作台回看每份独立run。归档台词只读；暂停/失败状态及原因保留，模型待审显示待审。归档resume返回中文409，不启动任务。选中历史版本回看原文，不用重新生成替代恢复，也不用旧数据库覆盖现有记录。

发布先运行后端、前端与导入安全检查。`build-natural-release.py prepare/build` 固定干净HEAD和已构建前端，仅创建新release并构建双镜像。`publish-natural-safe.py candidate` 对真实旧库快照连续导入两次并验证原记录；`publish` 才执行一致备份、导入、服务切换及健康检查。推荐稿必须是人工候选、completed、实际完整模型复核通过；待审稿和失败稿只能作为历史保留。

恢复内容以对应run和快照为准；恢复代码使用记录提交及helper源码。候选或正式发布失败按原发布工具的备份边界恢复，避免覆盖服务恢复后产生的新请求。`verify-evolution-public.py` 对公网历史、审阅标签、原文、前端资源、导出与归档拒绝续写做实际验证，不触发新生成。
